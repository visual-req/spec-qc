## 検査ルールの追加・保守方法

### ルールファイルの配置場所

- 汎用ルールファイル：`work/quality/quality_standard.md`
- 業界ルールファイル：同じディレクトリに配置することをお勧めします。例：
  - `work/quality/banking_quality_standard.md`
- 実行時にパラメータで追加のルールディレクトリを指定できます：
  - CLI：`java -jar spec-qc-*.jar scan -req ... --rules /path/to/rules_dir`
  - Web UI：「ルールディレクトリ」フィールドに入力します

### 業界の境界（業界外の誤スキャンの回避）

各品質ファイルの先頭に適用業界を宣言する必要があります。例：

```md
### 適用業界
- 适用行业：銀行/金融
```
*（注：パーサーが依存している可能性があるため、プレフィックス `适用行业：` はそのままにしてください。）*

- 汎用ルールの場合は次のように記述することをお勧めします：`适用行业：通用（跨行业）`（適用業界：汎用（業界横断））
- スキャン時に、環境変数で現在のスキャン業界を指定できます：

```bash
export SPEC_QC_INDUSTRY="银行"
```

業界が一致しないルールファイルはスキップされます（汎用ルールは常に使用可能です）。

### 個別ルールの推奨フォーマット

モデルの安定したヒットと出力を促進するために、ルールブロックの統一された構造を維持することをお勧めします：

```md
#### 123. ルールタイトル（トリガー条件と問題の本質を明確に記述する）
- 問題カテゴリ：XXX
- キーワード：キーワード「A/B/C」
- 問題の説明：なぜそれが問題なのかを1文で説明する
- エラーの例：典型的な例を1〜2つ挙げる（具体的であるほど良い）
- 解決策：実行可能な修正方法を提供する（必要に応じて表形式の出力 `suggestion_html` を要求する）
- 解決策のメリット：オプション
- 適用シナリオ：オプション（一般化による誤スキャンを制限・回避するために使用）
- 関連する品質基準：正確性/完全性/一貫性/保守性...
```

### 「提案セクション」を表として出力させる

あるルールの提案を表形式で提示したい場合は、ルールテキストで明確に要求し、表の列を説明してください：

- 用語集/用語の説明：用語集の表を要求する（用語/定義/範囲/例/備考）
- 権限：RBACマトリックスとデータ権限マトリックスを要求する
- 境界/例外：境界条件と期待される動作のリストを要求する
- ユーザージャーニー/オブジェクトジャーニー：ジャーニーマトリックスを要求する（横軸はライフサイクル）

システム側でも、特定のルールに対して強制的な表出力を適用しています（バックエンドのプロンプト制約を参照）。
